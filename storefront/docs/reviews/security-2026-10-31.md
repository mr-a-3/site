# Local security review — 31 October 2026

## Result and scope

Reviewed and fixed the local storefront, owner APIs, Bangladesh checkout, manual payments, image uploads and phone preview. This is a source review plus regression testing, not a penetration-test certification or a promise that every future deployment is secure. No publication was performed.

Existing brand, contact details, wallet settings, products, prices, layout choices, business records, uploaded media, backups and `.wrangler/state` were preserved. Live checkout testing deleted only the script's own verification order. Other security test records use an in-memory database.

## Fixes

- **Header scrolling:** replaced the sticky glass surface with fixed, composited geometry and reserved its original page height. Phone header remains at y=8px, height=64px, and desktop at y=8px, height=76px. Tested multiple scroll positions, cart opening/closing, light/dark themes and horizontal overflow. This verifies browser emulation; physical phone rendering can still vary by browser/device.
- **Request size limits:** JSON and image upload handlers now count streamed bytes and reject oversized inputs before buffering the entire request. Invalid UTF-8, malformed JSON, arrays/null instead of objects, and unsupported content types fail cleanly.
- **Public request throttling:** persistent atomic counters guard quote/place/track/activity endpoints. The LAN proxy separately limits actual socket peers, never trusting a supplied X-Forwarded-For header. It validates Host, Origin and JSON type, caps body size, and has request/upstream timeouts. In local preview the backend counter is shared, while the proxy supplies per-peer limits. Production per-IP limits assume the trusted Cloudflare ingress; this does not replace edge DDoS protection.
- **Checkout integrity:** prices, discounts, delivery charges, quantities, product colours and stock remain server-validated. A required colour cannot be omitted. Atomic insertion guards stock, request keys and reused wallet transaction IDs.
- **Payment updates:** customer-supplied verification is ignored. Only owner updates can verify a manual payment. Confirmation/shipping requires verification for wallets. Updates compare the current payment/status/timestamp, and admin submits its expected timestamp to reject stale screens.
- **Uploads:** only the supported raster signatures are accepted, with stronger PNG/JPEG/GIF/WebP checks and streamed 5MB limits. SVG and fake short PNG input are rejected. Uploads retain randomized keys and nosniff image serving. Signature checking is not a full image sanitizer.
- **Browser response protections:** per-response nonces authorize inline scripts; script policy avoids unsafe-inline, production avoids unsafe-eval, and form/action/base/object/frame restrictions are set. Added frame, permissions, cache and MIME protections. Browser checks showed no script/CSP errors.
- **Owner boundary:** local auth remains loopback-only, incoming identity headers are stripped by the local integration, production refuses the local test identity, and cross-site writes are rejected. Owner APIs and the local storage explorer remain unavailable through the phone proxy.
- **Dependencies:** patched Next, React, React Server Components, Vinext, Vite, Cloudflare tooling, Zod and vulnerable transitive packages. Zod defaults were migrated without resetting saved settings. Original dependency manifests are in `D:/site/backups/security-2026-10-31/`.

## Validation

- `node scripts/check-security.mjs`: streaming/body/type limits, per-peer and persistent throttling, price/quantity/colour tampering, atomic stock reservations, owner updates, stale payment conflicts, unverified payment guard, transaction reuse and nonce policies; SQLite is in memory.
- `node scripts/check-wallets.mjs`: wallet availability, transaction references, personal/merchant snapshots, totals and forged verification; mocked storage.
- `node scripts/check-security-live.mjs`: anonymous/forged-header access, origin checks, invalid links/prices/uploads, stale saves, headers and LAN exclusions; saved settings remain unchanged.
- `node scripts/check-checkout.mjs`: live COD pricing, order creation/idempotency, tracking privacy, owner transitions and refund bookkeeping; removes its exact verification order.
- TypeScript checks and production build passed. Both local URLs restarted through the existing automatic supervisor.

Audit JSON and build logs are in `logs/security-*.json` and `logs/security-build.txt`. The final production-dependency audit reports **zero known vulnerabilities**. The full dependency audit still reports **20 moderate advisories**, all in development tooling. These concern development tooling (the ESLint/minimatch and Drizzle/esbuild dependency chains). Forced old-version downgrades suggested by npm were not applied. Track upstream fixes; do not expose the development server publicly.

## Deployment boundaries still requiring configuration

- This is still the local preview. Public hosting must provide HTTPS and a trusted authenticated owner gateway. The present identity integration relies on the Sites/ChatGPT gateway; a generic standalone server must not trust user-supplied identity headers.
- bKash/Nagad are manual personal/merchant transfers, not an automated gateway. Verify receipt in the actual wallet before marking a payment verified; a transaction ID alone is not proof of payment.
- Customer Google/email authentication and courier merchant integration are not connected. Edge WAF/DDoS settings, production secrets and host-level controls were not configured or penetration-tested here.

## Reference guidance

Request validation, body limits, throttling and response protections follow the [OWASP REST Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html). Blur rendering considerations were checked against the [MDN backdrop-filter reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter). Dependency findings come from the installed lockfile's npm advisory scan, not a blanket assessment of feature exploitability.
